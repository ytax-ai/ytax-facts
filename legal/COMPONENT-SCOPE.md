Unchanged upstream expression keeps its status; the ytax revisions are ytax material. |
| `js/engine/` | The linked JavaScript engine (`factgraph.js`): a Scala.js link of `engine/fact-graph-scala/` at this release's pin together with the third-party Scala libraries listed in `factgraph.libraries.tsv`. Compiled IRS expression keeps its upstream status, compiled third-party code keeps its own license, and only the compiled form of the ytax changes is ytax material. The file is not modified after linking and carries no ytax header. The libraries' own license and notice files are in `third-party/`, indexed by `THIRD-PARTY-NOTICES.md`; they are third-party text, not ytax material. |
| `js/src/` and `js/scripts/periodDates.ts` | The TypeScript runtime that loads the linked engine. `persistenceWrappers.ts` is unchanged Direct File expression, compared with the pinned upstream file (`../provenance/release.json`), and carries no ytax header; `setupFactGraph.ts`, `constants.ts` and `flow/Path.ts` are adapted from Direct File and carry the scoped notice with their upstream path; the other files are original ytax build support with the SPDX header. |
| `js/scripts/generate-dictionary.sh`, selected JS manifests, `BUILD.md`, `docs/release/profile.json`, and `tools/build_release.py` | Build and release support, not the IRS engine. ytax material; any third-party expression keeps its own license. |

The PDFs under `prep/examples/` are synthetic example forms and input documents; they describe no real person. |
| Dependencies fetched by sbt, npm, or pip | Their own licenses apply. Its classifications describe copying and change relationships, not legal ownership findings. Source notices are changed in the source repositories before export; the exporter does not rewrite source bytes.
